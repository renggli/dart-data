### 2.1 Thread Recursion `depth` and Guard Distributive Expansion in Symbolic Integration

- [ ] **File**: `lib/src/symbolic/calculus/integration.dart` (lines 131–291, 1362–1557, 1709–1920, 2303–2396)
- **Root Causes**:
  1. **Lost `depth` parameter across `Add` and `_antiDerivMul`**:
     - `_antiDerivative` accepts `int depth = 0` (`line 135`), which guards the 8 expensive fallback passes at `line 226` (`if (depth < 2 && node is! Add && _hasUnevaluatedIntegral(result, variable))`).
     - However, `Add` (`line 153`) calls `_antiDerivative(term, variable, assumptions: assumptions)` without `depth: depth`.
     - `_antiDerivMul` (`line 1418`) does not accept `depth` at all! Worse, whenever an integrand has any constant factor (`constFactors.isNotEmpty` at `line 1436`), `_antiDerivMul` strips the constant factor and calls `_antiDerivative(varPart, variable, assumptions: assumptions)` with default `depth = 0` (`line 1443`)!
     - As a result, whenever `_tryIntegrationByParts` (`line 1744, 1748`), `_tryUSubstitution` (`line 2661`), `_tryAffineRadicalSubstitution` (`line 2397`), `_tryRationalTrigSubstitution` (`line 3606, 3632`), or `_tryHyperbolicRationalSubstitution` (`line 3715`) calls `_antiDerivative(..., depth: depth + 1)` on an expression with a scalar factor (such as `2 * ...` or `-1 * ...` or `1/2 * ...`), `depth` is immediately reset to `0`.
     - In `bondarenko#33` (`sqrt(x^2 + 1) * atan(x)^2`), this causes `_tryIntegrationByParts` to distribute `(1/2 * x * sqrt(1 + x^2) + 1/2 * asinh(x)) * 2 * atan(x) / (1 + x^2)` at `depth = 0`, triggering nested IBP and all 8 substitution passes recursively for `212–297ms`.
  2. **Unconditional numerator splitting in `_antiDerivMul` step 5 (`lines 1528–1547`)**:
     - When `varFactors` contains an `Add` factor `(t_1 + ... + t_k)` and `otherExpr` has a variable-dependent denominator `1 / D(x)` (such as `jeffrey#4`: `(5*cos(x)^2 + 4*cos(x) - 1) / (4*cos(x)^3 - ...)` or `moses#74`: `(2*x^6 + 5*x^4 + x^3 + 4*x^2 + 1) * exp(x^2) / (x^2 + 1)^2`), step 5 splits the product into $k$ separate calls `_antiDerivative(t_i * otherExpr)`.
     - Each of the $k$ calls fails and runs all 8 fallback passes (e.g. running Weierstrass substitution and $6 \times 6$ `apart()` 3 separate times in `jeffrey#4`, and running `u`-substitution 5 separate times in `moses#74`).
     - Even when the split terms fail to integrate, step 5 returns `Add([Integral(...), ...])`, which then causes `_antiDerivative` at `line 226` to run all 8 fallback passes a $(k+1)$-th time on the original `node`, and ultimately returns a fragmented sum of unevaluated `Integral`s instead of `Integral(original, variable)` (or instead of letting whole-node substitution solve the unsplit integrand first).
  3. **Unbounded numerator `p` in `_fractionalExponent` (`lines 2303–2313`)**:
     - `_fractionalExponent` checks `q >= 2 && q <= 6` but places no bound on `p.abs()`.
     - In `welz#47` (`(3 - 2*x)^(-41/2) * (2*x^2 + x + 1)^(-20)`), `p = -41` triggers `_tryAffineRadicalSubstitution`, substituting `x = (3 - u^2) / 2` and producing `u^(-41) * (1/2 * u^4 - 7/2 * u^2 + 7)^(-20)`.
- **Fix**:
  1. Thread `int depth = 0` through:
     - `Add` case in `_antiDerivative` (`line 153`): `_antiDerivative(term, variable, assumptions: assumptions, depth: depth)`
     - `_antiDerivMul` (`line 1418`): add `{Assumptions assumptions = Assumptions.none, int depth = 0}` and pass `depth: depth` to `_tryAntiDerivDiv`, `_antiDerivative(varPart, ...)` (`line 1443`), `_tryIntegrationByParts` (`lines 1503, 1506, 1517, 1521`), distributive expansion (`line 1540`), and polynomial expansion fallback (`line 1553`).
     - `_tryAntiDerivDiv` (`line 1077`): add `{int depth = 0}` and pass `depth: depth` to recursive `_antiDerivative` calls (`lines 1362, 1366, 1399, 1408`).
  2. In `_antiDerivMul` step 5 (`lines 1528–1547`):
     - If `otherExpr` has a variable-dependent denominator (`splitNumeratorDenominator(otherExpr).$2.dependsOn(variable)`), run `_antiDerivative` on the distributed terms with `depth: math.max(depth, 1)`, and if the distributed sum still contains any unevaluated `Integral` (`_hasUnevaluatedIntegral(distSum, variable)`), do **not** return the fragmented sum — fall through so `_antiDerivative` (`line 226`) tries whole-node substitutions on the unsplit expression and returns a single clean `Integral(original, variable)` if unsolvable.
  3. In `_fractionalExponent` (`line 2307`), require `p.abs() <= 12` (`if (p != null && q != null && p.abs() <= 12 && q >= 2 && q <= 6)`).

### 2.2 Pre-Check `polynomialDegree` Before Calling `.expand().simplify()`

- [ ] **Files**: `lib/src/symbolic/algebra/term_accumulator.dart` (lines 757–810), `lib/src/symbolic/calculus/integration.dart` (lines 1351–1412, 3028, 3627–3631, 3734, 4100)
- **Root Causes**:

    - $\deg(A \cdot B) = \deg(A) + \deg(B)$
    - $\deg(A^k) = k \cdot \deg(A)$ for non-negative integer $k$
    - Returns `null` immediately if any child is non-polynomial in `variable` (e.g. `Sin`, `Cos`, `Ln`, `Pow` with negative or fractional exponent).
  - Despite this, `extractPolynomialCoefficients` (`term_accumulator.dart:800-810`) calls `final expanded = expr.expand().simplify();` on line 801 **before** checking `polynomialDegree(expr, variable)`! Whenever `extractPolynomialCoefficients` is called as a pattern-matching probe on a non-polynomial expression (which happens dozens of times per integral in `_tryQuadraticRadical`, `_tryRepeatedQuadratic`, `_tryChebyshevBinomial`, `_tryGaussianAntiderivative`, `_tryCubicBinomialDenominator`, `_trySophieGermainQuartic`, `_tryBiquadraticDenominator`, `_tryPolynomialOverSqrtQuadratic`), it expands the entire expression first only to return `null`.
  - Similarly, in `lib/src/symbolic/calculus/integration.dart`:
    - `_tryAntiDerivDiv` (`lines 1352–1356`) calls `left.expand().simplify()` and `right.expand().simplify()` **before** checking `polynomialDegree(left, variable)` and `polynomialDegree(right, variable)` and before checking `degRight <= 24` / `degRight <= 12`. On `welz#47`, this expands `(2*x^2 + x + 1)^20` (and after `u`-sub, degree-121 `u^41 * (1/2*u^4 - 7/2*u^2 + 7)^20`) into hundreds of terms only to reject `degRight > 24`.
    - `_tryRepeatedQuadratic` (`line 3028`), `_tryRationalTrigSubstitution` (`line 3628`), `_tryPolynomialOverSqrtQuadratic` (`line 3734`), and `_tryDistinctLinearPartialFractions` (`line 4100`) also call `.expand().simplify()` inside `polynomialDegree(...)`.
- **Fix**:
  1. In `extractPolynomialCoefficients(Expr expr, String variable)` (`lib/src/symbolic/algebra/term_accumulator.dart:800`):
     - First check `if (!expr.dependsOn(variable))` and `if (polynomialDegree(expr, variable) == null) return null;` **before** calling `expr.expand().simplify()`.

     - Require `rawDegLeft != null && rawDegRight != null && rawDegRight >= 1 && rawDegRight <= 24` **before** calling `left.expand().simplify()` and `right.expand().simplify()`.
  3. In `_tryRepeatedQuadratic` (`line 3028`), `_tryRationalTrigSubstitution` (`line 3628`), `_tryPolynomialOverSqrtQuadratic` (`line 3734`), and `_tryDistinctLinearPartialFractions` (`line 4100`):

### 2.3 Canonicalize Input Before Differentiation & Avoid Quotient Numerator Expansion Blowup

- [ ] **Files**: `lib/src/symbolic/calculus/differentiation.dart` (lines 24–40, 434–468), `bin/sympy_integration_tests.dart` (lines 552–564)
- **Root Causes**:
  1. **Unsimplified input to `_differentiate` (`lib/src/symbolic/calculus/differentiation.dart:31-38`)**:
     - `DifferentiationExtension.derivative` starts with `var current = this;` without simplifying `this` first.
     - When `this` comes from `Expr.parse` or operator construction, a quotient `A / (B * C^19)` is represented as `Mul([A, Pow(Mul([B, C^19]), -1)])` rather than `Mul([A, Pow(B, -1), Pow(C, -19)])`.
     - Consequently, `_differentiateMul` (`lines 438-467`) sees a single denominator factor `right = Mul([B, C^19])` instead of `Pow(C, 19)`, falls into the generic quotient rule `((dLeft * right - left * dRight).expand()) / Pow(right, 2)`, and calls `.expand()` on `right`, expanding `C^19` into a degree-38 polynomial!
     - Simplifying `this` before `_differentiate` reduces `bronstein#3` derivative time from `173.2ms` (`21,870` AST nodes) to `7.6ms` (`3,101` AST nodes) (**22.7x faster**) and `welz#47` from `43.5ms` (`10,416` nodes) to `17.0ms` (`2,066` nodes).
  2. **Unconditional `.expand()` in `_differentiateMul` (`lib/src/symbolic/calculus/differentiation.dart:456-467`)**:
     - Lines 458–466 call `.expand()` on `_differentiate(left, variable) * base - exponent * left * _differentiate(base, variable)` and `_differentiate(left, variable) * right - left * _differentiate(right, variable)` even when `left` or `right` contains high-degree powers, radicals, or transcendental expressions, causing severe intermediate expression swell before `.simplify()` runs.
     - Furthermore, when `denFactors` has multiple distinct factors $D_1^{e_1} \cdots D_k^{e_k}$ ($k \ge 2$), lumping them into `right = Mul(denFactors)` and applying `(left' * right - left * right') / right^2` fails to cancel the common $D_i^{e_i - 1}$ factors, squaring the entire product denominator. Differentiating via the product rule over the simplified factors (or only applying the single-base quotient rule when `denFactors` is a single `Pow(base, exp)` or single polynomial factor, and only calling `.expand()` when the numerator is a low-degree polynomial) avoids squaring composite denominators.
  3. **Duplicate `antideriv.derivative(variable)` call in `bin/sympy_integration_tests.dart:552-564`**:
     - `_verifyDerivative` computes `antideriv.derivative(variable)` at line 554 and then computes `antideriv.derivative(variable)` a second time at line 561 when symbolic subtraction does not immediately simplify to `0`.
- **Fix**:
  1. In `DifferentiationExtension.derivative` (`lib/src/symbolic/calculus/differentiation.dart:31`), initialize `var current = simplify(assumptions: assumptions);`.
  2. In `_differentiateMul` (`lib/src/symbolic/calculus/differentiation.dart:447-468`), only apply the quotient rule when `denFactors` has a single factor (`denFactors.length == 1`), and only call `.expand()` on the numerator `(dLeft * base - exponent * left * dBase)` when both `left` and `base` have `polynomialDegree(..., variable)` $\le 4$ (otherwise let `.simplify()` combine terms without blowing up products). When `denFactors.length > 1`, let the general product rule (`lines 470-486`) differentiate each `Pow(base, -exp)` factor in place so denominators are not squared and expanded.
  3. In `bin/sympy_integration_tests.dart:_verifyDerivative` (`lines 552-564`), compute `final deriv = antideriv.derivative(variable);` once and reuse `deriv` for both the symbolic check `(deriv - integrand).simplify()` and the numerical evaluation fallback.

### 2.4 Short-Circuit `Expr.substitute`, Preserve Identity in `mapChildren`, and Deduplicate AST Boilerplate

- [ ] **Files**: `lib/src/symbolic/ast/expr.dart` (lines 84–99), `lib/src/symbolic/ast/operator.dart` (lines 18–198), `lib/src/symbolic/ast/function.dart` (lines 1–247), `lib/src/symbolic/ast/special_function.dart` (lines 1–548), `lib/src/symbolic/ast/lambert_w.dart`, `lib/src/symbolic/ast/piecewise.dart`
- **Root Causes**:
  1. **`substitute` traverses and reconstructs variable-independent subtrees with `isSimplified: false`**:
     - Every operator and function AST class overrides `substitute(String variable, Expr replacement)` to unconditionally recurse into all children and construct a new node with `isSimplified: false` (the default).
     - When substituting a variable (e.g. `uAntideriv.substitute('_u0', candidate)` in integration, or evaluating a Taylor coefficient or definite integral bound), every subtree that does **not** depend on `variable` is still traversed down to its leaves, re-allocated, and stripped of `isSimplified: true`. The subsequent `.simplify()` call is then forced to re-simplify every untouched subtree from scratch.
     - Short-circuiting `if (!dependsOn(variable)) return this;` yields a **4.7x speedup** (`111.0us` -> `23.6us`) on `substitute(...).simplify()`.
  2. **250+ lines of duplicate `substitute` overrides across 45+ AST classes**:
     - For every AST node that does not bind variables (everything except `Variable`, `Integral`, `Derivative`, `Limit`, `Sum`, `Product`), `substitute(variable, replacement)` is identical to:

       ```dart
       @override
       Expr substitute(String variable, Expr replacement) =>
           dependsOn(variable)
               ? mapChildren((c) => c.substitute(variable, replacement))
               : this;
       ```

     - Defining this once on `Expr` in `lib/src/symbolic/ast/expr.dart:94` eliminates all `substitute` overrides in `Add`, `Mul`, `Pow`, `Sin`, `Cos`, `Tan`, `Asin`, `Acos`, `Atan`, `Sinh`, `Cosh`, `Tanh`, `Asinh`, `Acosh`, `Atanh`, `Abs`, `Ln`, `Re`, `Im`, `Arg`, `Conjugate`, `LambertW`, `Piecewise`, `RelationalExpr` (`LessThan`, `LessEqual`, `GreaterThan`, `GreaterEqual`, `Equal`, `NotEqual`), `VariableFunction`, and all 28 classes in `special_function.dart`.
  3. **`mapChildren` always allocates a new node even when children are unchanged**:
     - In `UnaryExpr` subclasses, `Pow` (`BinaryExpr`), `Add`, `Mul`, `Piecewise`, and `VariableFunction`, `mapChildren(transform)` always allocates a new node with `isSimplified: false` even when `identical(transformedChild, child)` holds for all children.
     - Checking `identical` (e.g., in `UnaryExpr`: `final next = transform(expr); return identical(next, expr) ? this : _reconstruct(next);`, in `BinaryExpr`: `final nextLeft = transform(left); final nextRight = transform(right); return identical(nextLeft, left) && identical(nextRight, right) ? this : ...`, and similarly in `Add` and `Mul`) avoids allocations and preserves `isSimplified: true`, cached `hashCode`, and cached `freeVariables` across all tree passes (`_expandDoubleAngleTrig`, `_replaceUCandidate`, `_togetherExpr`, etc.).
  4. **Unnecessary `Set` allocations in `freeVariables` (`lib/src/symbolic/ast/operator.dart:56, 91, 143`)**:
     - `BinaryExpr.freeVariables`, `Add.freeVariables`, and `Mul.freeVariables` always allocate a new `Set` and wrap it in `Set.unmodifiable({...})`.
     - For `BinaryExpr` (such as `Pow(x, 2)`), when `right.freeVariables.isEmpty`, `left.freeVariables` is already an unmodifiable `Set<String>` and can be returned directly with zero allocations (and `const <String>{}` when both are empty).
     - For `Add` and `Mul` (such as `Mul([2, x])`), when 0 children have free variables, return `const <String>{}`; when exactly 1 child has non-empty `freeVariables`, return that child's `freeVariables` directly.
- **Fix**:
  1. ### 2.5 Optimize `BareissEngine` Exact Division & RREF and Deduplicate Factorization in `cancel`/`apart`

- [ ] **Files**: `lib/src/symbolic/linear/bareiss.dart` (lines 254–390), `lib/src/symbolic/algebra/rational.dart` (lines 76–92, 236–264, 483–567)
- **Root Causes**:
  1. **`BareissEngine._exactDivide` calls `.factor()` before `_polynomialLongDivide` (`lib/src/symbolic/linear/bareiss.dart:272-310`)**:
     - During Bareiss fraction-free determinant elimination (`lines 72-75`), `pPrev` is guaranteed by Sylvester's identity to divide `num = m[k][k] * m[i][j] - m[i][k] * m[k][j]` exactly.
     - However, `_exactDivide(num, den)` (`lines 282-285`) calls full multivariate polynomial factorization `num.factor()` and `den.factor()` **before** trying `_polynomialLongDivide(num, den)` (`line 305`)!
     - Moving `_polynomialLongDivide(num, den)` ahead of `num.factor()` speeds up a $4 \times 4$ symbolic Bareiss determinant from `9.49ms` to `1.74ms` (**5.5x faster**).
  2. **No `Number` fast-path in `BareissEngine._simplifyRatio` and `_simplifyDifference` (`lib/src/symbolic/linear/bareiss.dart:254-269`)**:
     - When `BareissEngine().solve(aMat, bMat)` solves the undetermined-coefficients system in `apart()` (`lib/src/symbolic/algebra/rational.dart:365`), the matrix entries are almost always exact `RationalNumber`s (`IntegerNumber` / `FractionNumber`).
     - Yet on every pivot elimination operation ($O(n^3)$ steps), `_simplifyRatio(num, den)` calls `num.expand().simplify()`, `den.expand().simplify()`, `(sNum / sDen).simplify()`, `_hasDiv(direct)`, `sNum.factor()`, and `sDen.factor()`; and `_simplifyDifference(a, b)` calls `(a - b).simplify()`, `_hasDiv(diff)`, and `diff.expand().simplify()`.
     - Adding `if (num is Number && den is Number) return num.div(den);` in `_simplifyRatio` and `if (a is Number && b is Number) return a.sub(b);` in `_simplifyDifference` bypasses AST construction, expansion, and factorization for numeric matrix entries.
  3. **Redundant denominator expansion and re-factorization in `together()` -> `cancel()` -> `apart()` (`lib/src/symbolic/algebra/rational.dart:76-92, 236-264, 483-567`)**:
     - `_togetherAdd` (`lines 483-567`) already factors each denominator, builds the factored LCM denominator `totalDen`, and cancels common factors via `cancelFactoredFraction(_factorPolynomial(totalNum, assumptions), totalDen)`.
     - When `apart()` (`line 237`) calls `cancel()`, `cancel()` calls `together()`, then expands the numerator and denominator (`expDen = denPart.expand().simplify()`, destroying the factored form of `denPart`), and re-factors `expDen` via `_factorPolynomial(expDen)`.
     - Then `apart()` at `line 258` calls `_factorPolynomial(denExpr, assumptions)` yet again!
- **Fix**:
  1. In `BareissEngine._exactDivide` (`lib/src/symbolic/linear/bareiss.dart:272-310`), execute `_polynomialLongDivide(num, den)` right after the fast-path `(num / den).simplify()` check (`line 279`), falling back to `cancelFactoredFraction(num.factor(), den.factor())` only when polynomial long division returns `null`.
  2. In `BareissEngine._simplifyRatio` (`line 254`), add `if (num is Number && den is Number && !den.isZero) return num.div(den);`. In `BareissEngine._simplifyDifference` (`line 265`) and row elimination (`line 148`), when `grid[r][c]`, `factor`, and `pivotEntry` are `Number`s, compute `grid[r][c].sub(factor.mul(pivotEntry))` directly.
  3. In `lib/src/symbolic/algebra/rational.dart`, factor `denExpr` without expanding already-factored `Mul`/`Pow` denominator trees in `cancel()` (`line 85`: pass `denPart` directly to `_factorPolynomial(denPart, assumptions)`, since `factorExpr` already handles `Mul` and `Pow` products without expanding them first!).
